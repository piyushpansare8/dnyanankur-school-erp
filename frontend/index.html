Fee Master

Academic Fee Structure Management

🔗 Connected Modules: Fee structures here auto-apply at Student Registration → fee plan. Drives Fee Collection installment amounts, Finance Center school fee ledger, and Concession calculations.
📅 Fee Plan Policy Dates — One-Time → 2-Installment → Full Payment Auto-Switch

Controls the combined School + Transport plan used in Fee Collection & Account Statements. Plan 1 = Tuition (One-Time lumpsum) + 1st Transport Installment, due 15 Jul; 2nd Transport Installment due 30 Dec. Plan 2 = Tuition Inst1 + Transport Inst1 due 30 Jul; Tuition Inst2 + Transport Inst2 due 30 Dec. Plan 3 = Full Annual Tuition + Full Transport, no due date. C3 = First Child/Sibling: Full Annual + Full Transport, due 30 Dec. C2 = Sibling 25% Off Tuition + Full Transport, due 30 Dec.   C1 = Teacher Child 50% Off + Full Transport. Miss Plan 1 by 15 Jul → auto-switch to Plan 2. Miss Plan 2 Inst1 by 30 Jul → auto-switch to Plan 3. One-Time Plan = Fee Master's "One Time Plan" tuition (paid in full) + 50% of the annual transport fee, due together by deadline ①; the remaining 50% transport is due by deadline ③. Miss deadline ① and the student auto-escalates to the 2-Installment Plan (Installment 1 due by ②, Installment 2 by ③); miss ② too and they escalate to the Full Payment Plan (full Annual Fee + full Transport, no discount) — no manual action needed.

    Shared with the Backup Engine — see ERP Version Detection for the same adapter from the backup side.
    📐Adapter Interface Contract

    Any future adapter must implement these five methods. The engine calls only these — never touches storage directly. 

    class StorageAdapter {
  async getAll(entity)         // → Array<Record>
  async getById(entity, id)    // → Record | null
  async upsert(entity, record) // → Record  (insert or update)
  async deleteById(entity, id) // → boolean
  async bulkUpsert(entity, records) // → { success, failed }
}
    ℹ️ To connect a cloud database, create a class that extends StorageAdapter, implement the five methods above, then call StorageEngine.setAdapter(new YourAdapter()). No other code changes needed.

    Database & API Readiness

    This build stores data in an in-memory data-access layer (DB object in the script). Every read/write goes through a single set of async-style functions — DB.getDocuments(), DB.saveDocument(), DB.logAudit() — so swapping the in-memory arrays for real HTTP calls to a backend (REST, GraphQL, Firebase, Supabase, etc.) only requires changing the implementation inside those functions, not the UI code.

    Current storageIn-memory (session only)
    Suggested production storePostgreSQL / MySQL + object storage
    File storageS3 / GCS / Azure Blob (see Cloud tab)
    Auth modelRole-based: Admin, Registrar, Staff, Viewer
